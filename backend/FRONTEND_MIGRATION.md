# Изменения API для frontend

Сводка изменений backend, которые нужно учесть при обновлении frontend. Старые запросы продолжают работать, кроме случаев, помеченных **обязательно**.

## Заявки

- **Обязательно.** Новый финальный статус `cancelled` («Отозвана автором»). Его нужно показать в метках, цветах и сортировке статусов: `views/ApplicationsView.vue`, `views/IncomingView.vue` (сейчас там обрабатываются только `rejected`/`expired`).
- Отзыв заявки автором (агент или физлицо): `PATCH /applications/:id/cancel`, тело `{ "comment"?: string }` (до 500 символов). Доступен до завершения сделки (`done`) и до истечения срока. Ответ — обновлённая заявка. Ошибки: `403` (не автор), `409` (заявка завершена, отклонена, истекла или уже отозвана).
- Фиксация клиента: заявка на клиента, уже закреплённого за другим агентом на этом объекте, возвращает `409` с текстом «Клиент уже закреплён за другим агентом по этому объекту». Показать `error` из ответа.
- **Обязательно.** Изменение ФИО и телефона клиента (`PATCH /applications/:id/client`) разрешено только агенту и только в статусе `sent`. Физлицу кнопку нужно скрыть (`403`). После подтверждения заявки — `409`.
- Менеджер (застройщик, администратор) не может выбрать статусы `expired` и `cancelled` (`400`). Их нужно убрать из выпадающего списка статусов.

## Уведомления

Новые типы `notification.type`:

| Тип | Кому | `meta` | Действие |
| --- | --- | --- | --- |
| `application_chat_message` | автору при ответе администратора; администраторам при сообщении автора | `applicationId`, `propertyId`, `messageId` | открыть `/application-chats?appId=<applicationId>` |
| `application_extended` | автору заявки | `applicationId`, `propertyId`, `expiresAt` | открыть заявку |
| `application_status` с `status: "cancelled"` | застройщику и администраторам | `applicationId`, `propertyId`, `status` | открыть входящие заявки |

`application_status` теперь также содержит `meta.propertyId`. Если статус менял администратор, такое уведомление получает и застройщик.

## Socket.IO

- Соединение больше не разрывается через 15 минут, когда истекает access-токен: оно живёт, пока активна серверная сессия (refresh-сессия). Событие с просроченным токеном той же сессии принимается.
- Сервер закрывает соединение при выходе, смене пароля, отзыве сессии или её истечении: приходит `auth_expired` либо `disconnect` с причиной `io server disconnect`. После такого отключения socket.io-client сам **не переподключается**. Рекомендуется: при `disconnect` с причиной `io server disconnect` сделать `/auth/refresh`, при успехе вызвать `socket.connect()` и повторить `subscribe` (сейчас `stores/notifications.js` подписывается один раз и после переподключения подписку не восстанавливает).
- Неверный токен в событии больше не сбрасывает уже выданные комнаты.

## Списки и пагинация

`GET /applications/mine`, `/applications/incoming`, `/properties`, `/news`, `/events/registrations` принимают необязательные `page` и `limit` (до 200). Их нужно передавать только вместе: один параметр без другого возвращает `400`. С ними ответ имеет вид `{ items, total, page, limit }`, без них остаётся массивом. Заявки дополнительно фильтруются по `status`. Для больших объёмов данных стоит перейти на постраничную загрузку.

## Профиль

- Пустой `phone` в `PATCH /users/me` означает «не менять»; прежний телефон в старом формате принимается как есть. Новый телефон должен быть российским.
- Компания обязательна для агента и застройщика (`400` при пустом значении). У физлица компания всегда пустая, поле можно скрыть.
- `PATCH /users/me/consents/marketing`: `accepted` должен быть настоящим boolean, `documentVersion` — до 50 символов.

## Объекты и мероприятия

- Администратор может создать объект или передать его только подтверждённому застройщику (`409` иначе). В выборе застройщика стоит запрашивать `GET /users/developers?status=approved`.
- Ручная смена статуса объекта на «продан» отклоняет отправленные заявки на этот объект.
- Мероприятие создаётся только с датой начала в будущем (`400`). В выборе даты стоит запретить прошедшие даты.

## Восстановление пароля (новые экраны)

- На странице входа — ссылка «Забыли пароль?» и форма email → `POST /auth/password/forgot` `{ email }`. Показать `message` из ответа (он одинаковый для существующих и несуществующих адресов). `503` — восстановление не настроено на сервере, `429` — слишком много запросов.
- **Обязательно для работы ссылок из письма.** Маршрут `/reset-password`: токен берётся из фрагмента URL (`location.hash`, `#token=…`), не из query. Форма нового пароля (8 символов – 72 байта) → `POST /auth/password/reset` `{ token, password }`. После успеха — перейти на вход; `400` означает, что ссылка устарела или уже использована (предложить запросить новую). Желательно сразу убрать токен из адресной строки (`history.replaceState`).
- После сброса все сеансы пользователя завершаются: открытые вкладки получат `401` и должны перейти на вход.

## Удаление аккаунта

- В профиле — кнопка «Удалить аккаунт» с подтверждением паролем: `DELETE /users/me` `{ password }`. После `200` очистить состояние авторизации и перейти на главную (cookie сервер очищает сам).
- Ошибки: `400` (неверный пароль), `409` с причиной в `error` (сделки в работе, у застройщика есть объекты, единственный администратор).
- Удалённые пользователи показываются в истории как «Удалённый пользователь».

## Управление мероприятиями

- Администратор: редактирование `PATCH /events/:id` (поля как при создании, все необязательные; `startAt` только в будущем) и отмена `POST /events/:id/cancel` `{ reason? }`. `409`: мероприятие уже началось, отменено или вместимость меньше числа записанных.
- В списках мероприятий у отменённых есть `cancelledAt` и `cancelReason`: показать пометку «Отменено» и скрыть кнопку записи.
- Участник: «Отменить запись» → `DELETE /events/:id/register` (до начала мероприятия).
- Новые типы уведомлений: `event_updated` и `event_cancelled` (участникам, `meta.eventId`), `event_registration_cancelled` (администраторам, `meta.eventId`, `meta.agentId`).

## Ошибки и лимиты

- Ошибки валидации приходят на русском в поле `error`, например «Поле «Телефон клиента» обязательно». Показывать можно напрямую.
- Вход ограничен 10 неудачными попытками на аккаунт за 15 минут, кроме ограничения 20 на IP. Ответ `429` содержит `error`.
- `POST /support` ограничен 10 обращениями за 15 минут с одного адреса, `POST /support/guest-session` — 30.
